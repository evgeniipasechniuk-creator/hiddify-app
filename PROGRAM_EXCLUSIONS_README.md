# Application exclusions 1.0 for Hiddify 4.0.4

This is a modification of [Hiddify](https://github.com/hiddify/hiddify-app), not an official Hiddify release. The upstream interface, connection controls and supported proxy protocols are retained. Modified sources are distributed under the original Hiddify licenses; see `LICENSE.md` and `core-overlay/HIDDIFY_CORE_LICENSE.md`.

## Что добавлено

В Windows откройте **Настройки → Исключения программ**. Выберите один или несколько файлов `.exe`, включите нужные исключения и нажмите **Применить**. Подключённый Hiddify переподключится; индикатор и текст показывают ход операции. Настройки сохраняются в `program_exclusions.json` рядом с настройками Hiddify. Выбор хранится по полному пути файла, без исключения всех программ с одинаковым именем.

Исключения применяются в режимах **VPN** и **VPN через службу**. В режимах системного или локального прокси экран явно показывает, что они не действуют. Перезапустите выбранную программу после применения, чтобы она создала новые соединения. Если сетевой трафик создаёт отдельный вспомогательный процесс, добавьте его `.exe` тоже. Явные настройки HTTP/SOCKS-прокси внутри исключённой программы нужно выключить. Запросы DNS Windows могут выполняться общей системной службой.

Например, можно исключить исполняемый файл терминала Альфа, оставив Telegram в обычной маршрутизации Hiddify. Исключение `python.exe` затронет все компоненты, работающие через этот файл Python. Для MOEX и Telegram внутри одного процесса нужны отдельные настройки соединения в самой торговой программе.

При обновлении установщик сохраняет копию прежних файлов программы в папке `application-exclusions-backup`. Профили и настройки в AppData сохраняются. Перед установкой отключите VPN и полностью выйдите из Hiddify через «Выход». Установщик останавливает службу туннеля на время замены файлов. После обновления запустите Hiddify и подключитесь вновь.

## Реализация

- Новая Windows-страница в основном меню настроек и разделе маршрутизации.
- Изменения сначала остаются черновиком; запись и переподключение происходят после Apply.
- Настройки записываются через временный файл, с копией предыдущей версии; ошибки не скрываются.
- Новое поле ядра `direct-process-paths`, отдельное от подписок и старого редактора правил.
- Правила `process_path_regex` сопоставляют весь Windows-путь, экранируют символы и не учитывают регистр. Выход — штатный direct, до общих правил маршрутизации. DNS-правило использует прямой resolver, когда движок видит владельца DNS-запроса.
- В других ОС и вне TUN эти правила не добавляются. Поддержка протоколов и остальные правила не меняются.
- Ошибка ChangeHiddifySettings или Restart передаётся интерфейсу, а не превращается в сообщение об успехе.

## Сборка и проверка

База приложения: `956177a3cd0e9613f3a4e3b336fcc626bc29f19a` (tag `v4.0.4`). База ядра: `cb21a8a0d84a42bcdea8d51336405f195a07c7a5` (tag `v4.0.4`). Flutter 3.38.5 / Dart 3.10.4; Go 1.25.6. Upstream dependency lock is retained; only flutter_test becomes an explicit dev dependency.

Локально проверены 6 тестов модели и хранения настроек, 4 теста интерфейса и 4 теста правил ядра. Анализ новых Dart-файлов проходит без замечаний. Сетевая DLL Windows x64 собрана со всеми штатными build tags; полный Dart-код приложения компилируется для Windows. Финальный нативный интерфейс, установщик и реальная маршрутизация на Windows остаются отдельными этапами проверки.

Лицензия Hiddify требует публикации модификации как открытого fork проекта и сборки выпусков через GitHub Actions. Workflow `.github/workflows/program-exclusions-windows.yml` запускается при push в `program-exclusions-v4.0.4` или вручную. Он проверяет исходники ядра, собирает DLL, выполняет тесты правил на Windows, тесты сохранения и интерфейса, собирает приложение на Windows 2022 и формирует установщик. Готовый файл появится в artifact `Hiddify-Application-Exclusions-1-Windows` только после успешного workflow.

Этот архив исходников не является установщиком. Пока GitHub Actions не завершился успешно, готовый Windows-выпуск не заявляется.

## Проверка на целевом компьютере после выпуска

1. Обновить установленную Hiddify 4.0.4, подключить прежний профиль в режиме VPN/TUN.
2. Добавить терминал в исключения и нажать Apply; проверить сообщение об успешной передаче конфигурации, затем перезапустить терминал.
3. В журнале соединений Hiddify проверить direct для выбранного процесса и прежний маршрут для Telegram; убедиться, что терминал получает свежие данные.
4. Отключить исключение и повторить проверку: новые соединения должны возвращаться к обычным правилам.
5. Перезапустить Hiddify и проверить сохранение списка. В режиме системного прокси проверить предупреждение об отсутствии действия исключений.

Отсутствие ошибок в тестах правил не подтверждает достижимость MOEX, доступ к Telegram, исправность прокси-сервера или свежесть данных брокера. Эти свойства проверяются на конкретном компьютере и подключении.
